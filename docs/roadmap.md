# Состояние проекта и roadmap

Обновлено: 6 октября 2026 года.

## Текущая оценка

| Область | Состояние | Оценка |
|---|---|---:|
| Основной сценарий заказа | Каталог → меню → quote → заказ → история → SSE-статусы работает сквозняком | 8/10 |
| Backend и данные | Транзакции, остатки, idempotency, outbox, адреса, миграции и OpenAPI реализованы | 8/10 |
| Web-клиент | Адаптивный интерфейс, auth store, профиль, адреса, localStorage и обработка ошибок реализованы | 8/10 |
| Тестирование | Unit, backend E2E и Playwright desktop/mobile есть; нужен изолированный E2E-контур в CI | 7/10 |
| Безопасность | JWT/refresh-ротация подключены к web; временная совместимость `X-User-ID` остаётся только для старых клиентов и E2E | 7/10 |
| Инфраструктура | Docker Compose и базовый CI есть; нет staging, наблюдаемости и управления секретами | 5/10 |
| Полнота продукта | Нет кабинета ресторана, реальной доставки, оплаты и уведомлений | 4/10 |

Сейчас это сильный технический прототип с законченным happy path, рабочей пользовательской сессией и сохранёнными адресами. Главный разрыв — часть интерфейса и интеграций всё ещё демонстрационные, а изолированный тестовый контур пока отсутствует.

## P0 — сделать пользовательский контур честным и безопасным

- [x] создать таблицы пользователей и refresh-токенов;
- [x] хранить пароль как bcrypt-хеш;
- [x] реализовать регистрацию и вход;
- [x] выпускать короткий JWT access token;
- [x] реализовать ротацию одноразового refresh token;
- [x] добавить `GET /api/v1/auth/me` и OpenAPI-контракт;
- [x] добавить auth store во frontend и автоматическое обновление access token;
- [x] сделать экраны входа, регистрации и профиля;
- [x] перевести web-клиент с фиксированного `X-User-ID` на Bearer token;
- [x] добавить таблицу и CRUD адресов доставки;
- [x] выбирать сохранённый адрес при оформлении;
- [ ] добавить E2E: регистрация → заказ → повторный вход → история;
- [x] добавить Playwright-сценарии регистрации, профиля и защиты приватных маршрутов на desktop/mobile;

Готово, когда новый пользователь может зарегистрироваться, оформить заказ, перезайти и увидеть только собственную историю.

Готово, когда всё показанное в интерфейсе приходит из API и каждое видимое действие работает.

## P1 — добавить второй полноценный пользовательский контур

### P1.1. Кабинет ресторана

- отдельная авторизация партнёра;
- список входящих заказов и live-обновления;
- принятие, отклонение и смена статуса;
- редактор меню, остатков и стоп-листа;
- время приготовления и история заказов;
- аудит действий сотрудников.

Это следующий лучший этап после P0: он демонстрирует двустороннюю платформу, а не только клиентскую витрину.

### P1.2. Уведомления и стабильный realtime

- выделить Notification Service;
- публиковать события заказа из outbox в брокер;
- заменить DB polling внутри SSE на подписку на события;
- добавить повторное подключение с `Last-Event-ID`;
- подготовить push/email-адаптеры.

### P1.3. Наблюдаемость

- Prometheus-метрики HTTP, БД и outbox;
- Grafana dashboard;
- OpenTelemetry traces между API и рестораном;
- correlation/request ID во всех логах;
- SLI: успешность заказа, p95 quote/create, задержка outbox.

## P2 — расширить предметную область

### P2.1. Доставка

- Courier Service и модель смены курьера;
- назначение курьера;
- координаты ресторана, клиента и курьера;
- геокодирование, зона доставки и ETA;
- отдельный интерфейс курьера;
- реальная карта вместо демонстрационной схемы.

### P2.2. Оплата

- sandbox платёжного провайдера;
- payment intent и webhook;
- идемпотентность платежей;
- отмена, полный и частичный возврат;
- Saga для согласования заказа, оплаты и доставки.

### P2.3. Production deployment

- API Gateway, TLS и rate limiting;
- secrets manager вместо dev-значений;
- сборка и публикация образов в registry;
- staging-контур и автоматический CD;
- резервное копирование PostgreSQL;
- k6-нагрузочные тесты и целевые SLO.

## Ближайшая последовательность

1. Добавить сквозной E2E повторного входа и истории заказов.
2. Убрать фиктивные сущности из web-клиента.
3. Изолировать E2E-базу и включить backend E2E в CI.
4. Реализовать кабинет ресторана.
5. Добавить наблюдаемость.
6. После этого переходить к Courier Service и оплате.
