# Состояние проекта и roadmap

Обновлено: 7 октября 2026 года.

## Текущая оценка

| Область | Состояние | Оценка |
|---|---|---:|
| Основной сценарий заказа | Каталог с поиском и фильтрами → меню → quote → заказ → история → SSE-статусы работает сквозняком | 9/10 |
| Backend и данные | Транзакции, остатки, idempotency, outbox, адреса, миграции и OpenAPI реализованы | 8/10 |
| Web-клиент | Адаптивный интерфейс, auth store, профиль, адреса и честная обработка недоступности API реализованы | 9/10 |
| Тестирование | Unit, изолированный backend E2E в CI и Playwright desktop/mobile закрывают критический путь | 9/10 |
| Безопасность | JWT/refresh-ротация подключены к web, customer API принимает только Bearer token | 8/10 |
| Инфраструктура | Docker Compose и CI с миграционными проверками есть; нет staging, наблюдаемости и управления секретами | 6/10 |
| Полнота продукта | Есть кабинеты клиента и ресторана; нет реальной доставки, оплаты и уведомлений | 6/10 |

Сейчас это сильный технический прототип с законченным happy path, тремя ресторанными fixture, рабочими кабинетами клиента и ресторана, пользовательской сессией и сохранёнными адресами. Главный разрыв — отсутствие редактора меню в кабинете, упрощённый realtime и отсутствие эксплуатационного контура.

- [x] добавить auth store во frontend и автоматическое обновление access token;
- [x] сделать экраны входа, регистрации и профиля;
- [x] перевести web-клиент с фиксированного `X-User-ID` на Bearer token;
- [x] добавить таблицу и CRUD адресов доставки;
- [x] выбирать сохранённый адрес при оформлении;

Готово, когда новый пользователь может зарегистрироваться, оформить заказ, перезайти и увидеть только собственную историю.

- [x] подключить кнопку профиля к регистрации, входу и выходу.

Готово, когда всё показанное в интерфейсе приходит из API и каждое видимое действие работает.

### P0.3. Изолировать интеграционные тесты

- [x] создать отдельный Compose-стек и базу `restaurant_delivery_test` на выделенных портах;

Готово, когда тесты нельзя случайно запустить против локальных пользовательских данных.

## P1 — добавить второй полноценный пользовательский контур

### P1.1. Кабинет ресторана

- [x] отдельный вход партнёра по API key с хранением только в `sessionStorage`;
- [x] адаптивная очередь входящих заказов и автообновление каждые 5 секунд;
- [x] принятие, отклонение и последовательная смена статуса;
- [x] сводка активных, новых и завершённых заказов;
- [ ] заменить polling очереди на realtime-события;
- [ ] редактор меню, остатков и стоп-листа;
- [ ] время приготовления и расширенная история заказов;
- [ ] роли сотрудников и аудит их действий.

Это следующий лучший этап после P0: он демонстрирует двустороннюю платформу, а не только клиентскую витрину.

### P1.2. Уведомления и стабильный realtime

- выделить Notification Service;
- публиковать события заказа из outbox в брокер;
- заменить DB polling внутри SSE на подписку на события;
- добавить повторное подключение с `Last-Event-ID`;
- подготовить push/email-адаптеры.

### P1.3. Наблюдаемость

- Prometheus-метрики HTTP, БД и outbox;
- Grafana dashboard;
- OpenTelemetry traces между API и рестораном;
- correlation/request ID во всех логах;
- SLI: успешность заказа, p95 quote/create, задержка outbox.

## P2 — расширить предметную область

### P2.1. Доставка

- Courier Service и модель смены курьера;
- назначение курьера;
- координаты ресторана, клиента и курьера;
- геокодирование, зона доставки и ETA;
- отдельный интерфейс курьера;
- реальная карта вместо демонстрационной схемы.

### P2.2. Оплата

- sandbox платёжного провайдера;
- payment intent и webhook;
- идемпотентность платежей;
- отмена, полный и частичный возврат;
- Saga для согласования заказа, оплаты и доставки.

### P2.3. Production deployment

- API Gateway, TLS и rate limiting;
- secrets manager вместо dev-значений;
- сборка и публикация образов в registry;
- staging-контур и автоматический CD;
- резервное копирование PostgreSQL;
- k6-нагрузочные тесты и целевые SLO.

## Ближайшая последовательность

1. Реализовать редактор меню, остатков и стоп-листа в кабинете ресторана.
2. Заменить polling очереди ресторана на realtime-события.
3. Добавить метрики, трассировку и correlation ID.
4. Подготовить staging-контур и управление секретами.
5. После этого переходить к Courier Service и оплате.
